# 同層續寫 (Same-Layer Continue)

模型回應被網路切斷時，直接在**同一層訊息**上接著寫下去。不新增訊息層、不新增 swipe。

## 安裝

SillyTavern →「擴充功能」→「Install extension」，貼上：

```
https://github.com/tony12345647/SillyTavern-SameLayerContinue
```

裝完重新整理頁面，「擴充功能」面板會出現「同層續寫」設定抽屜，魔杖選單會多一個「續寫本層」。

手動安裝的話，把整個資料夾放到 `SillyTavern/data/<你的使用者>/extensions/` 底下即可（舊版路徑是 `public/scripts/extensions/third-party/`）。

## 用法

- **魔杖選單 → 續寫本層**：對最後一則角色訊息續寫。
- **斜線指令 `/slcontinue`**：同上，方便綁進 QR 或腳本。
- **自動偵測**：回應結束後檢查是否被截斷，可選跳提示或直接自動續寫。

## 設定

| 設定 | 說明 |
| --- | --- |
| 啟用擴充 | 總開關 |
| 在魔杖選單顯示按鈕 | 關掉就只剩斜線指令 |
| 回應結束後自動檢查 | 自動偵測總開關 |
| 偵測到截斷時 | 跳提示／直接自動續寫／什麼都不做 |
| 同一層最多自動續寫次數 | 防止無限迴圈，預設 2 |
| 結尾沒有句末標點 | 判定規則之一 |
| 引號／括號／星號沒有閉合 | 判定規則之一，`**粗體**` 已排除 |
| 程式碼區塊沒有閉合 | 判定 ``` 數量是否為奇數 |
| 短於這個字數就不判斷 | 避免對超短回應誤判 |
| 續寫前先去掉結尾空白 | 讓接縫乾淨 |
| 續寫後同步回目前 swipe | 避免切 swipe 時內容跑掉 |
| 主控台偵錯訊息 | 排查用 |

設定面板底部有「測試偵測最後一則」，可以拿現有訊息調規則鬆緊。

## 注入了什麼

續寫是完整重跑一次 ST 的組 prompt 流程，所以這些**全部都在**，跟你手動按 Continue 一模一樣：

preset／預設集、世界書（含 @Depth 深度注入、遞迴掃描、sticky）、角色卡（description / personality / scenario / 範例對話）、作者註記、聊天記錄、Persona、正則、提示詞管理器的排序與開關。

擴充只額外接管「已寫好的那半段」怎麼送進去：

| 設定 | 說明 |
| --- | --- |
| 把已寫好的內容當 prefill 送出 | 開啟後模型收到的是文章本體接續，而不是一句「請繼續」。續寫時暫時覆寫 ST 的 continue prefill 選項，跑完自動還原 |
| 接縫處插入什麼 | **中文務必選「不插入任何字元」**。ST 預設是插一個空白，中文會在句子中間多出空格 |
| 自訂續寫指示 | 覆寫 ST 的續寫 nudge 文字。留空就用 ST 原本的 |

所有覆寫都是暫時的，續寫結束（含出錯）一定還原，不會動到你存起來的預設集。

## 實作說明

- 續寫一律呼叫 SillyTavern 內建的 continue，依版本自動選用：
  `executeSlashCommandsWithOptions` → `executeSlashCommands` → `getContext().generate('continue')` → 點擊 `#option_continue`。
  因為走原生路徑，所以同層追加、context 組裝、串流都跟你平常按 Continue 完全一致。
- 只對最後一則**角色**訊息作用。最後一則是使用者訊息時會直接擋下，不會誤生成新層。
- 自動續寫次數在你送出新訊息或切換聊天時歸零。

## 更新

設定面板最下面有版本號、「檢查更新」和「立即更新」。按下去等同對擴充資料夾做一次 `git pull`，完成後會跳提示要你重新整理頁面。`auto_update` 也開著，ST 啟動時本來就會自己拉。

發新版的流程：改完 code 推上 GitHub 時，**記得把 `manifest.json` 的 `version` 往上加**。ST 有些版本靠版本號決定要不要更新，忘了加會拉不動。

手動安裝（直接丟資料夾、沒有 `.git`）的話沒辦法自動更新，只能重新下載覆蓋。

## 續寫前清理（刪詞）

續寫之前先把指定字詞從上一層內容裡拿掉，再讓 AI 接著寫。用來把干擾的詞從上下文移除，讓續寫往別的方向去。

例：上一層是「我把20個蘋果放在購物車裡面，今天我要拿回」，清單裡加「蘋果」，AI 收到的是

> 我把20個放在購物車裡面，今天我要拿回

它就接著寫「去做成水果拼盤」——因為它沒看到蘋果，可以自由發揮成香蕉、芭樂什麼的。

### 兩種刪除範圍

| 模式 | 行為 |
| --- | --- |
| **只從送給 AI 的內容刪**（預設） | 聊天記錄裡的原文完全不動。續寫結束後自動把原文接回來，只保留 AI 新寫的那段。結果是「我把20個蘋果放在購物車裡面，今天我要拿回**去做成水果拼盤**」 |
| **直接從訊息刪掉** | 那些字永久從訊息消失。結果是「我把20個放在購物車裡面，今天我要拿回**去做成水果拼盤**」。有備份，可按「還原上次清理」救回 |

### 清單寫法

一行一條，純文字直接寫，括號星號會自動跳脫：

```
蘋果
香蕉
（待續）
/\[系統[^\]]*\]/
# 井字號開頭是註解，不會生效
```

想用正規表達式就寫成 `/pattern/flags`，`g` 會自動補上。寫錯的規則會被略過，不影響其他條目。

### 其他設定

**掃描範圍**預設整篇訊息；改成「只處理結尾 N 字」的話只掃最後 N 個字，適合那種只想清掉斷點附近垃圾、又怕誤刪前文的情況。

**「直接清理訊息」**按鈕不續寫，只把清單套到訊息上，拿來試規則對不對。

如果生成過程中模型沒有正常接續（整段重寫了），擴充接不回原文會跳警告並保留備份，按「還原上次清理」處理。

## 注意

- 如果 API 那邊本來就把回應截在 max tokens，續寫也只會再補一段而已，可能要按第二次。
- 完全沒收到任何字（0 長度）的情況，建議用 ST 原本的重新生成，續寫沒東西可接。
